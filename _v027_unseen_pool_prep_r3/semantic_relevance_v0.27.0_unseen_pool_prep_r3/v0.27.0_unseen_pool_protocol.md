
## Freshness scope (r3 correction)

A candidate is eligible only if it is absent from the **union of all historically consumed judge-calibration evidence**. At minimum this includes:

- `semantic_relevance_v0.27_development.v3.0.0.csv` (120 consolidated consumed cases), and
- the original 60-case `semantic_relevance_calibration.v0.5.0.csv` candidate set (with v0.4.0/v0.3.0 accepted only as identity-preserving fallbacks).

The r2 builder excluded only the consolidated 120-case set. That was insufficient because the original 60-case calibration set had also been inspected and used during judge development. r3 therefore excludes the union by ISBN and normalized title+authors before selecting any new candidate.

## Fresh candidate construction

The 60-case pool is generated from the actual raw semantic-retrieval path already used for judge calibration:

- 12 frozen queries, Q01-Q12.
- Four raw Chroma target ranks per query: 2, 10, 30 and 70.
- One deterministic random corpus candidate per query.
- Raw rank targets scan forward when a candidate is in the consumed 120-case development set or was already selected elsewhere in the new pool.
- The recorded `retrieval_rank` is the actual raw rank selected, not merely the target rank.
- The random candidate must be outside that query's retrieved top 250.
- All 60 candidate identities are globally unique and excluded against the consumed 120 cases by both ISBN-13 and normalized title+authors.

Case-slot mapping is frozen:

- T01 -> target raw rank 2
- T02 -> target raw rank 10
- T03 -> target raw rank 30
- T04 -> target raw rank 70
- T05 -> deterministic random candidate

## Human labeling

The builder generates a blind Excel workbook. The visible reviewer sheet contains query, title, authors and the exact canonical book description plus blank `human_score`, `human_reason`, and `review_status` fields. Retrieval source/rank is hidden to reduce anchoring bias.

The semantic relevance judge must not be run before all 60 human labels are final.

## Split

After 60/60 labels are imported back to the canonical CSV and authoring validation passes, `split_v0_27_unseen_pool.py` deterministically creates 30 validation cases and 30 final-holdout cases. The final holdout is immediately marked `LOCKED_DO_NOT_RUN`.

Use the 30 validation cases for the next evidence step. If judge/facet/scoring semantics change after validation, create a new revision and re-freeze before the one-time final holdout run.
